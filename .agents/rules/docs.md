# 文档：分层、落盘与导航

## 分层（不要两份真源）

- **`README.md`**：只保留定位、30 秒上手、目录结构、硬约束摘要、文档导航；
- **`AGENTS.md`**：AI 入口——项目前提、阅读顺序、硬不变量、纪律红线、高频命令、导航；
- **`.agents/`**：规则与场景技能（本目录），不承载语言/实现细节；
- **`docs/architecture.md`**：子系统地图与「改一处 → 跑什么」；
- **`docs/reference/<topic>.md`**：单一主题的细节（语言、类型、编译器、工具、测试……）；
- **GitHub issues（`label:debt`）**：**只记仍未关闭**的债务，每条带证据；文档引用写 `gh#N`；
- **历史**：已完成阶段、已落地决策、推翻旧决策的理由 → git 提交信息，不写进 `docs/`。

需要在两处提到同一件事时：一处写完整内容，另一处只写一句 + 链接。

## 探索完必须落盘

读几千行建立的理解若只留在会话里，会话一结束就没了。每完成一个主题的探查，立即写进
`docs/`（按上面的分层选落点）：

1. **数据流**：输入 → 各阶段 → 输出，每段的入口符号；
2. **不变量与陷阱**：什么必须保持、什么改动会破坏它；
3. **已知边界与缺陷**：工具/子系统**做不到**什么；
4. **导航**：某主题该看哪几个文件、哪几个函数。

**不要写**：能从源码直接看到的签名、行号（会漂移），以及 `vuna api` 已覆盖的接口清单。

## 写完接进导航

新文档必须在**两处**登记，否则等于不存在：

- `AGENTS.md` 的「文档导航」加一行；
- `README.md` 的「文档导航」表加一行（若是面向使用者的参考页）。

## 生成物：不读、不手改

- `seed/`：OCaml 信任锚点，只能经 `nix/seed/rotate.sh` 轮换；
- `docs/api.html`、`docs/.generated/errors.md`：由 `vuna doc` / `vuna dev errors gen` 生成；
- `result`、`.output`、`_scratch/`、`.local/`：本地产物，已 gitignore。

`docs/api.html` 是发布产物，不是探索工具；查接口用 `vuna api <Module>`。
