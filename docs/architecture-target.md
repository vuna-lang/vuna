# 终态架构：大方向、不变量与非目标

本文件描述 vuna **终态**形状与不可违反的边界。它回答"终态的编译器长什么样、哪些线永远不动"，
**不回答**"怎么实现"：实现路径、模块切分、数据结构、排期都不在这里。

三个文件分工，不互相复制：

| 文件 | 回答 |
| --- | --- |
| 本文件 | 终态方向、不变量、已决决策、非目标 |
| [architecture.md](architecture.md) | **现状**子系统地图：链路、入口、改动定位 |
| [reference/debt.md](reference/debt.md) | **当前**仍未关闭的缺口与缺陷 |

## 怎么用这个文件

提出任何新功能前，按顺序问三个问题：

1. **它属于哪一层？**（语言 / 编译 / 后端 / 工具 / 生态）——层次错位是补丁感的源头。
2. **已有通用机制能否表达它？** 不能，就先把需求翻译成一个通用语言特性，再加特判。
3. **它违反某条不变量吗？** 违反则先改本文件并说明理由，再动代码。

## 一句话终态

> 一个**小核心**（类型论 + 分层表示的编译管线 + 一张查询图 + 一个内容寻址存储），
> 上面长着**两个产品后端**、**一套语义优先的工具**、**一个把核心逼到极限的生态层**；
> 一切产物都是其输入内容的纯函数。

```text
生态层    vuna-web：DSL、SSR、HMR、响应式、API          （用户包，永不进 TCB）
工具层    LSP（语义优先）/ fmt / doc / test / profiler / 包管理
后端层    IR ──> native（自研运行时、服务器二进制）
              ──> wasm（浏览器 / 边缘）
              ──> OCaml（自举与互验，不发货）
编译层    CST → 宏/DSL 展开 → 名字解析 → 精化 → 擦除 → IR
语言层    QTT / 效应行 / 全性 / 模块 / 能力边界
             ▲                                        ▲
             └────── 查询图 + 内容寻址存储（横切）─────┘
```

横切那一层不是"又一层"，是两件基础设施：所有阶段、所有工具、所有后端都挂在上面，
没有例外。终态里任何绕开它们的机制，都是补丁。

## 终态能力清单

大方向粒度，每条只说明"终态有什么"，不说明"怎么做到"。

- **单一查询图**：编译的每个工作单元是一个纯函数节点，按内容寻址缓存；增量、并行、
  取消、可观测性都是它的属性，不是额外机制。
- **分层表示**：无损 CST、Core、擦除后 IR、后端 IR，一种表示只服务一个抽象层。
- **擦除后 IR**：显式、带类型、well-scoped、无元变量、无燃料预算，是所有后端的唯一输入。
- **两个产品后端**：native（自研运行时，产出服务器与桌面二进制）与 wasm（浏览器 / 边缘）；
  另有一个不发货的 OCaml 后端，只用于自举与互验。
- **语义优先的工具**：语法高亮、补全、跳转、格式化都从编译器的语义结果派生，
  不从文本模式派生。
- **宏与自定义 DSL**：语法是数据、按模块作用域；用户可定义宏与 DSL 语法，工具自动跟上。
- **内容寻址的包**：依赖可被哈希固定，产物与缓存跨项目、跨机器复用；哈希格式按
  "代码即内容"设计，身份模型可以渐进升级。
- **vuna-web 生态层**：HTML / SQL / CSS DSL、SSR、HMR、响应式、HTTP API、实时通道，
  全部作为用户包实现。

## 不变量

不变量指"终态下永远成立、违反即视为缺陷"的命题。每条都必须能说出它挡掉了什么。

1. **一种表示只服务一个抽象层**。相邻层之间只有显式转换，转换本身也是查询节点。
2. **一切产物都是其内容哈希的纯函数**。不存在"手工失效"的路径。
3. **只有一张查询图**。CLI、LSP、REPL、测试、文档、dev server 都是它的客户端。
4. **语法是数据且作用域化**。宏、DSL、运算符优先级共用同一套"可见表"机制。
5. **能力是唯一信任边界**。框架与工具链永远在 TCB 之外。
6. **一份 IR 驱动所有后端**。后端之间只差运行时契约，不差语义。
7. **工具从编译器派生，不从文本模式派生**。任何"按正则/文本规则"的工具行为都是缺陷。
8. **自举闭环**。终局不依赖 OCaml；历史源码级信任根保留归档，仅供审计与互验。
9. **确定性**。相同输入产生逐字节相同的产物；跨平台差异必须被显式定义，不能是意外。
10. **可观测**。每个工作单元都有 span，任何"慢"都能归因到一个节点。
11. **宏携带 span**。任何展开都能回溯到用户源码的原始位置，否则工具链整条失效。

## 已决决策

每条决策都记录"理由"与"代价"。代价不写出来的决策，等于没做决策。

| # | 决策 | 理由 | 代价 |
| --- | --- | --- | --- |
| D1 | 非总性只在 runtime；语言层不提供 `partial` / `assert_total` 逃生舱 | 特权必须显式、可列举、可拒绝 | "循环"只剩 runtime 组合子一个出口，组合子 API 下限被抬高 |
| D2 | 效应一次性续延；单一操作语义（CBV）；宿主交互走事件队列 | 两套操作语义会让差分测试与两端复用同时失效 | 外壳与 runtime 承担全部循环与事件分发 |
| D3 | 运行时内存用 Perceus 式 RC + 复用 | 与已有 0/1/ω 用量信息天然衔接 | RC 回收不了环，可变性需受能力与数据形状约束 |
| D4 | 宏终局是 typed macro / elaborator reflection，先做 AST→AST | 声明式宏够用一阵，reflection 才是终态 | 精化器要成为稳定库值；LSP 必须能跑宏并支持超时取消 |
| D5 | 内容寻址身份停在"依赖按哈希固定"，哈希格式按"代码即内容"设计 | 身份模型可以渐进，哈希格式不能返工 | **内容哈希、逻辑指纹、身份模型三者从一开始就分开**；依赖类型语言还需要 surface/code 双哈希，因此 D11 是它的前提 |
| D11 | 引入 `opaque` / `abstract` 定义修饰符 | 让 surface/code 双哈希真正生效：不展开的定义体只影响产物，不影响下游精化 | 多一个语言特性，用户要理解"能不能展开"的差别 |
| D6 | client/server 由框架切分；边界用类型表达；切分在构建图里做 | 胶水与平台演进不该进编译器 | 切分正确性靠构建图检查与测试，不再由编译器保证 |
| D7 | 自举终局用 wasm seed；OCaml 退出日常路径但不删除 | 可移植的二进制根，同时保留审计与互验腿 | 源码级信任根消失，需靠归档与互验补偿 |
| D8 | interp 保留"纯求值"，退役"第二执行语义"；`vuna interp` 可在 run 路径成熟后退 | 保留 normalization，去掉语义分叉 | REPL / test / goal 需改接查询图与后端 |
| D9 | 单一查询图 + 内容寻址存储是横切基础设施，所有消费者是客户端 | 消灭多套缓存与多个入口 | 需要会话概念与常驻会话的内存策略 |
| D10 | vuna-web 是生态层、是核心的验收测试，永不进 TCB | 框架不得倒灌核心 | 每个 web 需求都必须先翻译成通用语言特性 |

## 非目标

明确不做，且不因为"顺手"或"别人有"而做：

- 不引入 LLVM / MLIR 作为后端基础设施（TCB 与自举哲学都不允许）。
- 不做第二套类型检查器、第二套 codegen、第二套加载语义。
- 不提供动态逃生舱：无运行时反射、无动态派发、无 `any` 类类型。
- 不在核心里出现 web 专有词汇或特判（`html` / `sql` / `jsx` / `dom` 都不属于核心）。
- 不为每种 DSL 手写编辑器插件；工具语义化是唯一路径。
- 不为并行而并行、不为多后端而多后端、不为宏而宏。
- 不走"先做框架、再回头补语言"的顺序。

## 依赖顺序

依赖关系是**四条轨道 + 三个汇合点**，不是一条阶梯；只写"谁是谁的前提"，不写排期。

```text
轨道 A（后端）    IR → OCaml-via-IR → wasm → native → 服务器外壳
轨道 B（工具语言） CST → 语义工具（高亮/格式化/查询）→ 宏/DSL → vuna-web
轨道 C（基础设施） 哈希格式 → 查询图 → 内容寻址身份（依赖按哈希固定 → 包身份 → 代码即内容）
轨道 D（自举）     归档 OCaml seed → native 自举 → wasm seed
```

- **汇合点一（A × C）**：查询图把编译单元当节点 —— dev server / HMR / 增量都从这里长出来。
- **汇合点二（B × C）**：语法表与宏展开进查询图 —— 宏可缓存、LSP 可超时取消。
- **汇合点三（A × B × C × D）**：vuna-web —— 需要 A 的 wasm、B 的宏、C 的构建图、D 的可移植产物。
- **IR 的第一个消费者是现有 OCaml 后端**（以逐字节一致为门禁），wasm 是第二个。
  理由：先证明 IR 保语义，再承担新运行时；wasm 需要先有 GC/字符串/IO 才能开始验证。
- **可独立先行、且不返工**：确定性编码与标准哈希、无损 CST、查询骨架。
  三者都是"加法"：不要求任何人先相信新架构。

每一层的"完成"由**该层的差分门禁**定义，而不是由时间定义：

| 层 | 出口门禁 |
| --- | --- |
| 哈希格式 | 编码 roundtrip；同输入跨进程/跨机器同摘要 |
| 查询图 | 新旧路径 audit 差分（同诊断、同产物） |
| IR | OCaml-via-IR 与直连 Core 的产物逐字节一致 |
| wasm / native | 与 OCaml 产物行为差分一致 |
| 宏 / DSL | 展开后 span 覆盖完整 + 格式化幂等 + 工具可跳转 |
| vuna-web | 应用级 e2e（SSR + hydration + 一次数据往返） |

## 变更纪律

- 推翻任一已决决策：改本文件对应行，并在提交信息里写明"推翻 Dx：理由"。不静默改写。
- 新增不变量：必须说明它挡掉了什么具体缺陷，否则它只是一个愿望。
- 本文件不记录阶段进展与历史；已完成、已推翻的细节进 git 历史。
- 实施细节写入对应主题参考页；本文件永远保持方向粒度。
