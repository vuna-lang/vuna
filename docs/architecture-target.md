# 终态架构：大方向、不变量与非目标

本文件描述 vuna **终态**形状与不可违反的边界。它回答"终态的编译器长什么样、哪些线永远不动"，
**不回答**"怎么实现"：实现路径、模块切分、数据结构、排期都不在这里。

三个文件分工，不互相复制：

| 文件 | 回答 |
| --- | --- |
| 本文件 | 终态方向、不变量、已决决策、非目标 |
| [architecture.md](architecture.md) | **现状**子系统地图：链路、入口、改动定位 |
| [reference/debt.md](reference/debt.md) | **当前**仍未关闭的缺口与缺陷 |

## 怎么用这个文件

提出任何新功能前，按顺序问三个问题：

1. **它属于哪一层？**（语言 / 编译 / 后端 / 工具 / 生态）——层次错位是补丁感的源头。
2. **已有通用机制能否表达它？** 不能，就先把需求翻译成一个通用语言特性，再加特判。
3. **它违反某条不变量吗？** 违反则先改本文件并说明理由，再动代码。

## 一句话终态

> 一个**小核心**（类型论 + 分层表示的编译管线 + 一个输入寻址对象库），
> 上面长着**两个产品后端**、**一套语义优先的工具**、**一个把核心逼到极限的生态层**；
> 一切产物都是其输入内容的纯函数。

```text
生态层    vuna-web：DSL、SSR、HMR、响应式、API          （用户包，永不进 TCB）
工具层    LSP（语义优先）/ fmt / doc / test / profiler / 包管理
后端层    IR ──> native（自研运行时、服务器二进制）
              ──> wasm（浏览器 / 边缘；受限后端，无进程/网络/stdin）
              ──> OCaml（自举与互验，不发货）
编译层    CST → 宏/DSL 展开 → 名字解析 → 精化 → 擦除 → IR
语言层    QTT / 效应行 / 全性 / 模块 / 能力边界
             ▲                                        ▲
             └────── 输入寻址对象库（横切）───────────┘
```

横切那一层不是"又一层"，是两件基础设施：所有阶段、所有工具、所有后端都挂在上面，
没有例外。终态里任何绕开它们的机制，都是补丁。

## 终态能力清单

大方向粒度，每条只说明"终态有什么"，不说明"怎么做到"。

- **可观测性是一等设施**（不变量 10 的落地形态）：事件模型固定为 Chrome Trace Event
  JSONL（`vuna-obs 1`），任何 vuna 应用都能用 `Base.Data.Obs` / `Base.Data.Obs.Span` 埋 span、
  计数与采样；开关分级（`VUNA_OBS=0..3`）、关闭路径零成本、产物默认带 `#line` 让
  DWARF 直指 `.vuna`；工具是 `vuna dev obs`（summarize / convert / render）与外部生态
  （perf / Chrome / speedscope / 火焰图）的换算。规范：[observability.md](reference/observability.md)。
- **单一输入寻址对象库**：一切可复用产物按输入摘要寻址；增量、并行、
  取消、可观测性都是消费者/调度层的属性，不是额外缓存。
- **分层表示**：无损 CST、Core、擦除后 IR、效应机器、后端 IR，一种表示只服务一个抽象层；
  每层一个类型、一个校验入口、一个确定性 dump（见「分层表示」）。
- **擦除后 IR**：显式、带类型、well-scoped、无元变量、无燃料预算，是所有后端的唯一输入。
- **两个产品后端**：native（自研运行时，产出服务器与桌面二进制）与 wasm（浏览器 / 边缘）；
  另有一个不发货的 OCaml 后端，只用于自举与互验。wasm 是**受限后端**：契约上限是浏览器
  WASI 能提供的能力子集；进程、信号、raw 网络、线程、stdin、符号链接、阻塞 sleep 不在
  契约内（契约与现状见 [reference/wasm.md](reference/wasm.md)「后端契约与边界」）。
- **语义优先的工具**：语法高亮、补全、跳转、格式化都从编译器的语义结果派生，
  不从文本模式派生。
- **宏与自定义 DSL**：语法是数据、按模块作用域；用户可定义宏与 DSL 语法，工具自动跟上。
- **内容寻址的包**：依赖可被哈希固定，产物与缓存跨项目、跨机器复用；哈希格式按
  "代码即内容"设计，身份模型可以渐进升级。
- **vuna-web 生态层**：HTML / SQL / CSS DSL、SSR、HMR、响应式、HTTP API、实时通道，
  全部作为用户包实现。

## 不变量

不变量指"终态下永远成立、违反即视为缺陷"的命题。每条都必须能说出它挡掉了什么。

1. **一种表示只服务一个抽象层**。相邻层之间只有显式转换，转换本身也是对象库节点。
2. **一切产物都是其内容哈希的纯函数**。不存在"手工失效"的路径。
3. **只有一个输入寻址对象库**。CLI、LSP、REPL、测试、文档、dev server 都是它的客户端。
4. **语法是数据且作用域化**。宏、DSL、运算符优先级共用同一套"可见表"机制。
5. **能力是唯一信任边界**。框架与工具链永远在 TCB 之外。
6. **一份 IR 驱动所有后端**。后端之间只差运行时契约，不差语义。
7. **工具从编译器派生，不从文本模式派生**。任何"按正则/文本规则"的工具行为都是缺陷。
8. **自举闭环**。终局不依赖 OCaml；历史源码级信任根保留归档，仅供审计与互验。
9. **确定性**。相同输入产生逐字节相同的产物；跨平台差异必须被显式定义，不能是意外。
10. **可观测**。每个工作单元都有 span，任何"慢"都能归因到一个节点。
11. **宏携带 span**。任何展开都能回溯到用户源码的原始位置，否则工具链整条失效。

## 分层表示

每层只有一种类型；相邻层之间只有一个显式转换函数（total，输入带上层的全部信息），
每层配一个校验入口与一个确定性 dump。不允许「靠调用顺序维持当前处于哪个阶段」。

| 层 | 类型 | 该层负责的不变量 |
| --- | --- | --- |
| CST | 无损具体语法树（节点 + span + trivia） | 逐字节还原源码；trivia 属于树 |
| Ast | surface 语法 | 只表示源码写出的构造（含糖） |
| Rast | 解析后语法 | 名字是身份（局部 / 全局 / 内建 / 宏 / 洞），糖已消失 |
| Core | 类型论核心 | 带类型、元变量、隐式参数与用量标注 |
| 擦除后 Core | Core 规范化 | 无元变量、无隐式、无擦除位可达 |
| IR | 运行时形状 | 显式、带类型、well-scoped、无元变量 |
| 效应机器 | 显式帧与续延 | 五个机器原语 + 帧纪律，三端同一语义 |
| 后端 IR | 目标形状 | 只差运行时契约与目标文本 |

**准入**：满足任一条才新增一层类型——(a) 节点语义变了（源层节点在目标层没有意义）；
(b) 有独立消费者或独立缓存身份（另一个进程/工具要消费它）；(c) 能表达上层表达不了的
不变量（例如 binder 集合里没有擦除位、每个 binder 有类型）。

**不新增类型**：规范化（抽象层不变，例如 ANF、去糖）与 pass（同一层内迭代）都保持同类型，
但规范化必须有幂等断言，pass 必须在前后跑该层的校验入口。层数不是目标：每加一层就多一次
全树遍历、一份校验与 dump，并且每加一个语言特性要多改一处。

## 已决决策

每条决策都记录"理由"与"代价"。代价不写出来的决策，等于没做决策。

| # | 决策 | 理由 | 代价 |
| --- | --- | --- | --- |
| D1 | 非总性只在 runtime；语言层不提供 `partial` / `assert_total` 逃生舱 | 特权必须显式、可列举、可拒绝 | "循环"只剩 runtime 组合子一个出口，组合子 API 下限被抬高 |
| D2 | 效应一次性续延；单一操作语义（CBV）；宿主交互走事件队列 | 两套操作语义会让差分测试与两端复用同时失效 | 外壳与 runtime 承担全部循环与事件分发 |
| D3 | 原生后端用**保守根集 + 分代标记-清扫**：沿 `rbp` 链整帧扫根，年轻代按分配预算先收、整堆按连续次数与晋升压力触发。wasm 后端用 WasmGC（宿主 tracing GC） | 续延已由库机器执行，机器状态全是堆/栈上的普通值，没有栈拷贝；对非移动 GC 来说保守扫根已经足够，逐 call 栈图/槽 kind 只会引入漏根风险。深递归按扫栈成本抬阈值（[performance.md](reference/performance.md)「槽 kind 分布」）。Perceus RC 仍不做：dup/drop 需要精确指针与生命周期，且 `IORef` 的环收不了 | 非移动老代 → 仍有内部碎片、不压缩；写屏障点分散在模块与运行时（`IORef` / cleanup / list 原地改接）；移动/压缩要等精确指针与槽 kind 全部可判定（debt D125） |
| D4 | 宏终局是 typed macro / elaborator reflection，先做 AST→AST | 声明式宏够用一阵，reflection 才是终态 | 精化器要成为稳定库值；LSP 必须能跑宏并支持超时取消 |
| D5 | 内容寻址身份停在"依赖按哈希固定 + 包身份接线"：`identityHash` 进 manifest/registry/pin/fetch/check，不做分发服务器 | 身份模型可以渐进，哈希格式不能返工 | **`contentHash` / `ifaceHash`·`implHash` / `identityHash` 三者从一开始就分开**；依赖类型语言还需要 iface/impl 双摘要（包级 `pkgIfaceHash` / `pkgImplHash`），因此 D11 是它的前提；分发真实性仍是非目标 |
| D11 | 引入 `opaque` / `abstract` 定义修饰符 | 让 iface/impl 双摘要真正生效：`ifaceHash` 不含不展开体（不影响下游精化），`implHash` 含它（只影响产物） | 多一个语言特性，用户要理解"能不能展开"的差别 |
| D12 | 摘要只固定**不可变源**：`git`+`rev` / `url` 必填 `hash`，`path` 依赖不写摘要 | 完整性（取源）与新鲜度（判脏）是两条链：新鲜度已由 `siHash` → `miIfaceHash` → `miDepHashes` 负责，改依赖源码不该动上游 manifest | `path` 依赖不可复现；发布前必须转成 `git`/`url` |
| D13 | 一个依赖图内同一包名只能出现一次（无版本号共存） | 无版本命名空间，规则最简；包名只参与"同包可见"判定 | 无法共存同名包的两个版本，只能改名/分叉 |
| D14 | registry = 内容寻址对象集 + **可选**静态索引；无服务器、无账户、无签名 | 当前无 TLS 能力；网络/账户不进 TCB 或 seed；传输外置给 `git`/`curl`/Nix | 来源可信性由用户选定的 URL 决定；无撤销；索引只是便利层 |
| D15 | 单一 store 根、两类生命周期：缓存族（派生、可删）与包对象族（取源、显式获取、跨项目存活）；获取显式、构建离线 | 缓存可删可重建，包对象必须跨会话/跨项目存活；一个根才有单一 framing/地址与 GC 口径 | 仍是同一棵树：clean/gc 必须按族作用域（包对象在 `objects/pkg/`），且无引用计数 GC（roots 只追加） |
| D6 | client/server 由框架切分；边界用类型表达；切分在构建图里做 | 胶水与平台演进不该进编译器 | 切分正确性靠构建图检查与测试，不再由编译器保证 |
| D7 | 自举锚点**当前**是 OCaml（`seed/`，同时是语义 oracle）；方向是 native 自举成熟后用 native 产物（`.s` 文件集）当锚点，OCaml 后端可在那之后退役并归档；wasm 不做自举、不设 wasm seed | native 产物只需要 `cc`/`as`/`ld` 且字节确定；wasm 仍只能跑浏览器 / 边缘能力子集，不能承担自举所需的宿主面 | 自举链平台锁定 x86-64 Linux（其它平台用发布二进制）；OCaml 退役后固定点从「独立实现互证」降级为「同一 codegen 自洽」，跨后端差分 oracle 需由 suite + wasm 交叉承担（[bootstrap.md](reference/bootstrap.md)「锚点演进」） |
| D16 | wasm 产物以 WAT 为 canonical；`.wasm` 由两段外部工具生成——`wasm-tools parse` 汇编、`wasm-opt`（binaryen）优化；WAT 仍不进 Git | 文本可审查、布局稳定可 diff；二进制交给成熟工具 | `.wasm` 字节依赖 `wasm-tools` 与 `wasm-opt` 两个由 Nix 固定的版本；WAT 布局不承诺跨版本稳定 |
| D8 | interp 保留"纯求值"，退役"第二执行语义"；`vuna interp` 命令已删除，纯求值只在 `vuna test` / REPL 内部使用 | 保留 normalization，去掉 CLI 语义分叉 | 第二执行语义（`runEffectProgram` 临时包）仍待清理；REPL / test 需改接对象库与后端 |
| D9 | 单一输入寻址对象库是横切基础设施，所有消费者是客户端 | 消灭多套缓存与多个入口 | 目录视图与 roots 需要并发/GC 规则 |
| D10 | vuna-web 是生态层、是核心的验收测试，永不进 TCB | 框架不得倒灌核心 | 每个 web 需求都必须先翻译成通用语言特性 |
| D17 | 包内依赖方向是**包格式的一部分**：`vuna.toml` 的 `[layers]` 声明层（= 模块前缀 = 目录）及允许的直接依赖，由 loader 在 import 时强制；不用「拆包」表达方向（[packages.md](reference/packages.md)「层约束」） | 方向是包的语义契约，应该随包一起被校验、被缓存身份覆盖；拆包会把一个编译单元切成多个包，代价远大于收益 | 层内 / 向下但跨子系统的 import 不受约束；只在需要严格方向的层上写表；层表与目录不同构时只能靠改目录（不改表）来纠正 |
| D18 | **语法层是「parser 发射的无损树 + AST 作为其上的类型化投影」**，不是「AST + 旁挂 trivia 流」 | 现状的 AST 已被表层信息占用（`EParen`/`EInfix`/`EBacktick`/`ESect*`/`EAnn` 是 parser 中间产物、`EFloat` 存原始文本、`EInterp` 存 `"""` 标记、`[]`/`()` 靠名字反推），而 trivia 与字节 span 又没有一处权威（注释归属靠 554 行 span 启发式，模式 span 缺字节偏移），CST 节点树的区间已由 parser 发射（`NodeEvent`），且与 AST 的 span 同源（同一构造的首 token → 末 token 之后）；分支节点带先序 id（节点身份，span 可改写而 id 不变），AST 起点 → id 的桥已由夹具锁定。但注释归属仍走扁平 span 启发式：锚点集合是**渲染器的挂载点**而不是纯语法种类（局部函数后续 clause 有 `binding` 节点但不挂注释），所以树不能单独替换 `anchorSpans`——必须先有投影。工具与宏都没有可信的「源码位置 → 语法位置」映射 | parser 边解析边发射树 ⇒ 改 parser 与 seed（要分步 rotation）；双写期必须有一条断言锁住「树视图 == 旧 AST」，否则变成两个真源；所有消费者（Fmt/Lint/LSP/Index/Doc/Repl）只能逐个搬 |
| D19 | **工具 pass 的形状是 `(PkgContext, Text) -> Check R`**：包上下文（roots / 模块图 / fixity 声明表 / lint 配置）每包构建一次、不可变、可内容寻址；文件级工作是纯函数 | 现状把包级信息散在 `FixityEnv` 的两张关联表里，且 fixity 声明表逐文件重算、`vuna.toml` 每文件读两次；实测 lint 的单文件固定成本 30–350 ms（规则遍历只占 ~14 ms）。这让「按文件并行」放大而不是缩短成本 | 需要先把上下文抽成显式值并改掉现有 `FixityEnv` 的隐式缓存；`--max-warnings` 的全局聚合与 LSP 的进程内路径要一并改成同一份配置来源 |
| D20 | **能力由 target 声明，不作为拒绝新增原语的理由**：IR 运行时契约的每个符号携带「哪些 target 支持」，后端实现或声明不支持；`compile --target T` 在 IR 校验阶段就拒绝（不是退到后端插件才报错） | 原语是否存在与某后端是否实现它本来就是两件事：wasm 已有 `RtUnsupported` → 代码生成期 `Err` 的机制，native 同理。「wasm 没有 X 所以不能加 X」是把实现现状误当成设计边界 | 能力矩阵要从两份手写字符串夹具变成契约数据，并与后端表做一致性校验；新原语必须同时落「声明 + 全部后端实现或声明」，编译器本身只知道查询契约 |
| D21 | **并发能力可补（fiber / 协程 / 线程都算候选），但语义契约先行**：任务体必须是 `Eff Nil a`；handler 栈不继承；续延不跨 domain 恢复（每 domain 一个调度器，fiber 不迁移）；`eff-boundary` 守卫对并发同样生效 | 语言里并存着完整调度器机制与已被删除的库 API（`prim_sched*` 完整、`Base.EffSched` 不存在、`dtp_async_fork/await` 触达不到），半成品是最差的状态；「单线程调度器是唯一并发路径」只是实现现状，不是不可改的基石 | 选 Domain 并行要同时付观测代价（`ITIMER_PROF` 只有主 domain，需每 domain 独立 timer + 合并）；三端实现进度不一致时，只能靠契约声明表达「不支持」，不能假装支持 |

## 非目标

明确不做，且不因为"顺手"或"别人有"而做：

- 不引入 LLVM / MLIR 作为后端基础设施（TCB 与自举哲学都不允许）。
- 不做第二套类型检查器、第二套 codegen、第二套加载语义。
- 不提供动态逃生舱：无运行时反射、无动态派发、无 `any` 类类型。
- 不在核心里出现 web 专有词汇或特判（`html` / `sql` / `jsx` / `dom` 都不属于核心）。
- 不为每种 DSL 手写编辑器插件；工具语义化是唯一路径。
- 不做包分发协议（签名 / 撤销 / 透明日志 / 账户 / 多源索引）；传输与信任锚外置给
  `git` / `curl` / Nix（D14）。
- 不引入归档/解压原语来支持 tarball 依赖；`url` 只接受规范对象文件（primitive 轨道另议）。
- 不为并行而并行、不为多后端而多后端、不为宏而宏。
- 不把 wasm 后端做成系统级运行时：进程 / 信号 / 网络 / 线程 / stdin 不在契约内
  （[reference/wasm.md](reference/wasm.md)）。
- 不走"先做框架、再回头补语言"的顺序。

## 依赖顺序

依赖关系是**四条轨道 + 三个汇合点**，不是一条阶梯；只写"谁是谁的前提"，不写排期。

```text
轨道 A（后端）    IR → OCaml-via-IR → wasm → native → 服务器外壳
轨道 B（工具语言） CST → 语义工具（高亮/格式化/查询）→ 宏/DSL → vuna-web
轨道 C（基础设施） 哈希格式 → 输入寻址对象库 → 内容寻址身份（依赖按哈希固定 → 包身份 → 代码即内容）
轨道 D（自举）     归档 OCaml seed → native 自举 → native 产物（.s）种子
```

- **汇合点一（A × C）**：对象库把编译单元当输入摘要 —— dev server / HMR / 增量都从这里长出来。
- **汇合点二（B × C）**：语法表与宏展开进对象库 —— 宏可缓存、LSP 可超时取消。
- **汇合点三（A × B × C × D）**：vuna-web —— 需要 A 的 wasm、B 的宏、C 的构建图、D 的可移植产物。
- **IR 的第一个消费者是现有 OCaml 后端**（以逐字节一致为门禁），wasm 是第二个。
  理由：先证明 IR 保语义，再承担新运行时；wasm 需要先有 GC/字符串/I/O 才能开始验证。
- **新后端之前先冻结运行时契约**：IR 只引用目标中立的运行时符号，OCaml 实现是参考；
  新后端按同一契约重实现运行时（GC/字符串/I/O/一次性续延），否则「一份 IR 驱动所有后端」
  只是结构口号。契约是 IR 层的一部分（`Ir.Runtime`），不是某个后端的私有约定。
- **可独立先行、且不返工**：确定性编码与标准哈希、无损 CST、查询骨架。
  三者都是"加法"：不要求任何人先相信新架构。

每一层的"完成"由**该层的差分门禁**定义，而不是由时间定义：

| 层 | 出口门禁 |
| --- | --- |
| 哈希格式 | 编码 roundtrip；同输入跨进程/跨机器同摘要 |
| 输入寻址对象库 | 新旧路径 audit 差分（同诊断、同产物）；clean/gc 作用域互不误删 |
| 内容寻址身份 | 依赖身份 = 依赖包 `pkgIfaceHash`；产物身份 = `pkgImplHash` + 布局摘要；同源跨目录地址一致；注释变更不脏依赖方/不重跑 codegen；`opaque` 体变更只换本包产物 |
| IR | OCaml-via-IR 与直连 Core 的产物逐字节一致 |
| wasm / native | 与 OCaml 产物行为差分一致 |
| 宏 / DSL | 展开后 span 覆盖完整 + 格式化幂等 + 工具可跳转 |
| vuna-web | 应用级 e2e（SSR + hydration + 一次数据往返） |
